# OK-94 OpenClaw consumer validation — 2026-08-11

No credentials, token contents, raw evidence, or diagnostic payloads are stored
in this record.

## Live baseline (`ok-ai`)

- OpenClaw is running and reports one MCP server named `platform-diagnostics`.
- The server uses the streamable-HTTP adapter endpoint and allowlists exactly
  `get_platform_health`, `investigate_workload`, and
  `collect_diagnostic_evidence`.
- OpenClaw's live MCP probe reaches the adapter and reports three tools.
- The OpenClaw ServiceAccount cannot read Pods.
- The running pre-OK-94 pod still has a projected Kubernetes ServiceAccount
  token and the legacy kubectl binary. This violates the stronger ADR-021
  consumer boundary even though the ServiceAccount currently has no useful RBAC.

## Chart 0.2.0 validation

`make verify-mcp-consumer` renders the chart and verifies:

- no Role, RoleBinding, ClusterRole, or ClusterRoleBinding is emitted;
- ServiceAccount token automount is disabled on the ServiceAccount and Pod;
- the upstream OpenClaw image replaces the kubectl derivative;
- Exec is denied;
- only the three ADR-021 tools are exposed through the configurable MCP adapter;
  and
- the agent preserves diagnostic provenance and sanitizes Jira/GitHub/docs
  handoff.

## Remaining live step

Chart 0.2.0 has not been rolled out by this change. After publication and an
approved deployment, run:

```bash
cd platform/ai/openclaw
make verify-mcp-live KUBECONFIG=~/.kube/ok-ai.yaml
```

The live check passes only when both the ServiceAccount token and kubectl are
absent and OpenClaw still reports the restricted MCP registration.
